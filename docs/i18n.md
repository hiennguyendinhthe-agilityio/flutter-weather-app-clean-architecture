# i18n

## Translation
- Library: https://pub.dev/packages/intl_utils

### Steps


1. Insert the following key:value as below:

```json
    {
        ...
        "welcomeTitle": "Welcome to Banking Consumer"
    }
```

2. Run script for generate l10n files (located at `core/resources/l10n_generated` folder)

```
melos run dev:generate:i18n
```

3. Then, get the translation by insert following code to right place

```dart
S.of(context).welcomeTitle
```

Example:
```dart
child: Text(S.of(context).welcomeTitle)
```

## Naming

>Style: `camelCase`

### The `general` namespace

We add a `general` prefix to store translations that are likely to be used throughout app. This prevents having duplicate keys all over app

When add this namespace for common terms, try to avoid long text and nested. Keep it simple and thus manageable.

Bad:

    "generalButtonSaveText": "Save"

Good:

    "generalSave: "Save"
### The `{FEATURE_Name}` namespace
We add a prefix to store translations that are likely to be used within a feature.

Bad:
```
payFeatureStartAnotherPaymentTextButton
```

Good:
```
payStartAnotherPaymentTextButton
```

### The `page` namespace
We add a prefix to store translations that are likely to be used within a page.

Avoid naming too abstract and avoid too close to the actual content, it will have trouble knowing what it actually says and changing text

Bad:

```
homePageParagraph1
homeSubtitle1
```
Good:

```
homePageWelcomeText
homePageSignUpButtonLabel
```

### The error messages namespace
For validation error messages, add a `error` prefix before keys
```
"errorInvalidEmailFormat": "Email is invalid format"
```

### Form
Localizing form elements is a great example for i18n keys, move translations to the `{FORM_NAME}Form` prefix before keys
```
"loginFormEmailLabel": "Email",
"loginFormEmailPlaceholder": "myname@email.com"
```
